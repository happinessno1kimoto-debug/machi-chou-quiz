# note有料記事 収益化プロジェクト(社内体制版)

「副業・お金の稼ぎ方」ジャンルで、1日1本ペースで有料note記事を作る運用です。以下の6部門体制で分業し、人間(オーナー)の仕事は**企画への「OK」と最終価格の決定のみ**にすることを目標にしています。

## 部門体制

| 部門 | 役割 | 担当 |
|---|---|---|
| リサーチ担当 | 毎朝、noteで500円クラスで売れている記事を収集し、「1年後も売れ続けそうな普遍テーマ」だけを抽出 | Claude(定期実行の企画フェーズ) |
| 企画担当 | リサーチ結果と過去の実績(`topics-log.md`)を照らし、次に書くべきテーマを10本提案 | Claude(定期実行の企画フェーズ) |
| **人間(オーナー)** | **10本の提案から1本を選び「OK」。最終価格を決定** | あなた |
| 執筆担当 | 4,000字・500円想定のnote記事を、無料公開パートと有料パートの境界を設計して1本仕上げる | Claude(承認後の制作フェーズ) |
| 検品担当 | 別セッション(別AI視点)が「AIっぽい言い回し」を検出し、一人称の体温ある文章に直す | サブエージェント(Agent tool) |
| デザイン担当 | note表紙画像と告知用画像のデザイン案を10パターン作成 | Claude + designスキル(Artifactキャンバス) |
| 営業担当 | X告知ポストを30本作成し、投稿スケジュール案を用意 | Claude(承認後の制作フェーズ) |

## 運用フロー(2段階)

### フェーズA:企画会議(毎朝6:00 JST・自動実行)

1. **リサーチ担当**: noteで売れている(目安500円前後)有料記事の傾向を調べ、一過性のトレンドではなく「1年後も需要が続きそうな普遍テーマ」だけを候補に残す
2. **企画担当**: `topics-log.md`(過去に書いたテーマと結果)と照らし合わせ、重複を避けつつ次の10本のテーマ案をランキング形式で提案(各案に「なぜ売れると考えるか」を一言添える)
3. 提案をチャットに提示し、**人間の回答待ちで停止**(この段階では記事執筆・画像・X投稿文は作らない)

### フェーズB:制作(人間が「OK」+価格を伝えた後、自動で連続実行)

4. **執筆担当**: 承認されたテーマで、4,000字前後・無料/有料の境界を設計した記事下書きを作成
5. **検品担当**: 別のサブエージェントを立てて記事を読ませ、「AIが書いたような定型表現・説明口調」を検出し、一人称の実体験として体温のある文章に書き直す(Claude自身の自己校正ではなく、独立した第三者視点でのチェックとして分離)
6. **デザイン担当**: designスキルでnote表紙+告知画像のデザイン案を10パターン、Artifactキャンバスとして作成(ユーザーがPNG/PDFで書き出して使用)
7. **営業担当**: X告知ポストを30本(切り口違い・時間帯違い)作成し、投稿スケジュール案(日時の割り振り)を用意
8. `node note-drafts/tools/build-kit.mjs` を実行し、「公開キット」(下記)を最新化してArtifactを再公開
9. `topics-log.md` に本日の実績を追記、コミット&プッシュ

## 公開キット(スマホ用まとめページ)

記事本文・表紙デザインへのリンク・X告知30本を、スマホでコピペしやすい1枚のページにまとめたものです。日付タブで過去分にも切り替えられます。

**URL: https://claude.ai/code/artifact/8668557c-cba1-4df9-859f-e6a95cf3d144**

- `note-drafts/tools/build-kit.mjs` が `note-drafts/YYYY-MM-DD/{article.md, x-posts.md, design-brief.md}` を自動で読み取り、`note-drafts/tools/kit-template.html` に埋め込んでHTMLを生成する
- 生成物はArtifactとして上記URLに毎回上書き公開する(`Artifact`ツールで同じURLに対して再publish。新しいURLを作らないこと)
- 実行例: `node note-drafts/tools/build-kit.mjs /tmp/.../kit.generated.html` → 生成されたファイルをArtifactツールで同じURLに publish
- 生成物(`kit.generated.html`)自体はリポジトリにコミットしない(ソースの `article.md` 等から毎回再生成される派生物のため)

## 現状できること / できないこと

- ✅ リサーチ・企画提案・記事執筆・検品・表紙デザイン案・X告知文と投稿スケジュール案の作成
- ✅ Gitでの下書き管理(ブランチ `claude/paid-note-monetization-8n02pz`)
- ❌ note.comへの実際の投稿(note側の認証情報が未連携)
- ❌ Xへの実際の投稿・予約投稿(X API連携が未設定)
- ❌ 表紙画像の最終PNG書き出し(Claude側では自動生成できず、Artifactキャンバス上でユーザーが書き出す必要あり)

note.com / Xへの自動投稿を有効にするには、それぞれの認証情報(note投稿用トークン、X APIキー等)が必要です。連携が整うまでは、営業担当が作った30本のX下書きと投稿スケジュール案を人が確認し、手動または別ツールで予約投稿してください。

**検証済みの制約(2026-08-23):** このClaude Code Remoteのクラウド実行環境は、組織のネットワークポリシーにより `note.com` へのアウトバウンド通信自体がブロックされています(プロキシで403拒否を確認済み)。そのため、noteのログインCookieを渡してもらってもブラウザ自動化(Playwright等)による投稿はこの環境からは実行不可能です。ローカルPC(ネットワーク制約のない環境)で動かす自動化スクリプトを別途用意すれば可能性はありますが、このセッション内では実現できません。以後、この方式は再提案しないこと。

## ジャンル方針

**副業・お金の稼ぎ方**(2026年note市場リサーチに基づく方針)

- 「副業」のような一般論ではなく、「AI活用×副業」「スキマ時間×月◯万円」のように **具体的な数値目標・手法** を切り口にする
- 一過性のトレンドではなく、**1年後も需要が続く普遍テーマ**を優先(リサーチ担当のフィルター基準)
- 実体験ベース(やってみた・失敗談込み)で信頼性を出す
- 無料部分でしっかり価値を出し、有料部分で「具体的な手順・テンプレート・数値」を出す(いわゆる「立ち読みで満足させない」設計)
- 価格は当面300〜500円程度でレビューを積み上げる方針(高単価は実績が付いてから、最終判断は人間)

## 注意事項(コンプライアンス)

- 「絶対」「必ず稼げる」等の断定的な収益保証表現は使わない(特定商取引法・景品表示法上のリスク)
- 実体験ベースの記述は誇張しすぎない
- 他者の有料コンテンツの文章・構成をそのまま模倣(盗用)しない。あくまで「売れる型」を参考にしたオリジナル記事を書く
- 検品担当が書き直す際も、事実関係(数値・手順)は変えず、あくまで言い回しのみ調整する
